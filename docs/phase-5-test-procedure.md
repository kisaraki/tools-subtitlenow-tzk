# Phase 5 測試操作

本文件是結案驗收程序。依使用者安排，目前開發流程不要求金鑰、不執行真實雲端；以下命令由結案時的使用者手動操作。人工測試內容以自有或已授權內容為準；五語與品質案例沿用 Phase 3／4 程序。

目前可核對的狀態見 [Phase 5 驗收表](phase-5-acceptance.md)。像素／控制項與真實視覺矩陣分開記錄，不用一般測試數量替代實機結果。

## 離線工程驗證

依序執行 cargo fmt --check、cargo clippy --locked --all-targets --all-features -- -D warnings、cargo test --locked、cargo build --locked、cargo build --locked --release。即時測試與重度依賴編譯分開，失敗保留紀錄，不放寬正式過期界線來通過測試。

原生離線測試使用自有視窗（多數隱藏；最小化／恢復案例短暫以不啟用方式顯示）、mock timeline／provider 與指標為空的 WM_TIMER／WM_COMMAND 路徑，驗證通知、取消及控制項內容。它不能驗證字幕畫面排版、實際滑鼠穿透、硬體音訊或雲端準確度。

一般 cargo test 會由父測試在隔離程序執行 60 次隱藏 GUI 循環，暖機後分三批查核 GDI／USER 資源。內部 isolated_ui_resource_fixture 只由這個父測試帶入專用 marker 執行，不要直接執行全部 ignored tests。此測試不擷取、不讀正式憑證、不連服務；它只涵蓋本次 GUI 資源，不外推為完整 backend 或長時間播放驗收。

## 結案互動測試

互動視窗的首選流程是執行 --ui，在固定的 OpenAI（ChatGPT）／Gemini 遮蔽欄位輸入所選服務的 API 金鑰，再明確選取程序、服務、五語／Auto 及品質，按開始。欄位留空會讀取所選服務的既有 Windows 認證；不得把金鑰貼到聊天、設定或檔案。切換服務保留兩組獨立輸入但不互相轉移；開始只取用所選欄位，兩組欄位與復原紀錄均清空，停止後重新開始需再次手動輸入（或留空使用認證）。金鑰欄位只在結案驗收手動操作，開發流程不使用正式金鑰。

如需安全儲存，另在對應欄位輸入並明確按該列的「儲存」；不需來源選取、不啟動雲端。這個操作會取代該服務在 Windows 認證管理員的既有值，清空該列輸入，另一列保持。儲存狀態與服務端權限驗證不同；錯誤應明確回報未儲存，不能顯示成功。執行期間兩組欄位與儲存按鈕停用。詳細步驟見 [固定金鑰介面](api-key-ui.md)。

確認來源與服務未選取時開始停用，清單更新不選取其他來源；運行時所有設定停用。停止後等待回收／解鎖，在同一視窗重新選來源、服務或品質再開始，驗證每次是新 Session、無舊字幕。根據程序建立時間拒絕過期來源；系統／跨程序／無法驗證來源不應出現在可啟動清單。

確認來源清單實際圖示、名稱、PID 與標題相符；選取後顯示串流狀態、訊號、峰值、音量與靜音。無圖示時明確顯示無法取得，未知峰值時隱藏量表。持續變動音量、展開清單、辨識期間查看活動，確認選項與 SideChat 回看位置保持；來源消失／程序身分不同時不套用另一個程序的圖示或峰值。讀值只代表所選音訊工作階段，不將無訊號當作辨識故障。

以下步驟保留指定 PID 的命令列視窗模式，供比較及診斷使用。

1. 使用 --list-sources 確認來源、程序樹／音訊工作階段與獨立 PID。
2. 在互動式終端機手動執行下列其中一個命令，把 `<PID>` 換成實際來源；旗標不包含金鑰。

```powershell
cargo run --locked -- --translate-window-pid <PID> --provider openai --language en --quality standard --interactive-key
cargo run --locked -- --translate-window-pid <PID> --provider gemini --language ja --quality high --interactive-key
```

3. 在本機隱藏提示手動輸入所選服務 API 金鑰，不貼到聊天、命令列、設定或檔案。提示完成前不開啟視窗／worker；若取消提示，不應開始擷取或連線。
4. 視窗應顯示相符的 PID、供應商與音訊／文字送出提示。最小化或隱藏的啟動視窗不得開啟啟動限制；恢復後才能接續。確認來源字幕只出現在視窗，stdout 不出現逐字稿。
5. 切換 SideChat／BottomSubtitle／Dual，確認來源 Session、連線與字幕順序延續，沒有第二份音訊送出或重啟辨識。搜尋與手動回看只影響 SideChat；底部維持最新字幕。
6. 點「工作階段 → 停止辨識與翻譯」，內容立即清除，先顯示正在停止再顯示已停止。等待期間的舊結果不可回填；停止後不再送音訊／要求。關閉視窗後程式應退出且無 helper／backend 遺留。
7. 分別在準備連線、辨識、翻譯、重試及初始化失敗情境關閉，確認取消與 join。來源退出、無效憑證、網路／速率限制需呈現錯誤或同服務重連；不得改用另一供應商。
8. --ui 可在停止並回收後於同一視窗重新選擇／啟動；固定 PID 命令仍須關閉並重新指定。確認新 Session 無舊字幕。依五語、Auto、三種品質與既有應用程式矩陣分別驗證，未測項目維持未驗證。

回看時反白原文／翻譯並持續播放，確認新字幕／暫定修訂不把畫面捲回底部，也不消除仍保留項目的選取。超過 64 筆而淘汰最舊項目時，仍存在的項目保持位置；正在看的項目被淘汰則移至最早保留項目、取消失效選取。搜尋後停止、重連或重新開始時，搜尋框與結果必須一起清空；「回到即時」清除搜尋並返回最新字幕。

在 SideChat／BottomSubtitle／Dual 各模式最小化控制視窗，確認底部字幕隱藏、字幕更新不自行還原視窗或搶走其他應用程式焦點；恢復後按所選模式顯示並維持同一 Session。回看期間最小化並持續播放，再恢復確認仍顯示相同保留項目。準備連線時最小化不得放行來源提示的啟動門檻；恢復後才接續。原生 mock 的 active-window 查核不能替代真實前景／工作列與鍵盤驗收。

## 視覺與效能

檢查 100／125／150／175／200% DPI、負座標多螢幕、拖曳／鎖定／穿透、中文＋原文／中文 Only、長文字與暫定修訂。透過「字幕外觀」切換三種字型、八種字級、描邊／陰影、0／25／50／70／100% 背景不透明度與 1–6 行，確認白字不隨背景淡化、行數限制不遮住其他視窗區域、雙語模式先保留中文。小工作區域可能只能容納較少行，完整文字仍由 SideChat 回看；完全透明時拖曳需點字形／效果區域。背景與字緣的單元像素測試不能當成可讀性驗收。

「側邊位置」預設靠右，切換靠左／靠右／自由移動，確認位於控制視窗所在螢幕的工作區域內、Session／內容／連線不變。將控制視窗拖至另一個 DPI 螢幕，停靠時於拖移結束重新靠該側；自由移動可自行調整位置與大小。確認來源圖示、下拉列高度、活動文字／量表、服務選項、金鑰、開始／停止、搜尋與歷史互不重疊，較小螢幕或較長文字如有裁切要記錄，不能因幾何模型通過而標示視覺通過。

「字幕螢幕」依序選主螢幕／各裝置，確認位於選定工作區域內；將字幕拖至不同 DPI 螢幕，確認字形重新繪製。更新清單及拔除選定螢幕時，應明確提示暫置主螢幕且保留原偏好；重新選擇可清除提示。外觀及螢幕切換應維持相同 Session／連線、字幕順序及單一管線。

選「跟隨來源所在螢幕」，將所選程序的可見視窗移至另一台螢幕，確認字幕在工作區域變更後重新定位，混合 DPI 字形清楚。相同程序多視窗時確認同 PID 前景／最大面積選擇；同一螢幕內移動時字幕不反覆跳動。來源未選、來源退出／身分不符、視窗最小化／隱藏時提示原因且保留位置；恢復後重新跟隨並清除提示。音訊子程序沒有頂層視窗時，應提示而非擅自選父程序，並可改用指定螢幕。這是結案人工矩陣，自有測試視窗的原生查詢成功不等同於全部應用程式通過。

量測翻譯完成至顯示與端到端延遲，記錄 P50／P95／最大值、丟棄與重連次數。33 ms 通知週期不是效能證據；未完成真實量測前不宣稱低於 100 ms 或首字幕低於一秒。
