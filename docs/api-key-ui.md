# 固定 API 金鑰介面

2026-10-09 依使用者「chatGPT / Gemini 的金鑰輸入應有固定使用者介面」實作。這是目前階段內的明確 UI 修正，不啟動新 Phase。正式金鑰仍留至結案時由使用者手動輸入，開發期間不索取／讀取／覆寫正式憑證，也不自動啟動服務測試。

執行 `cargo run --locked -- --ui`，從「服務與金鑰設定」開啟固定 OpenAI（ChatGPT）與 Gemini API 兩列，每列都有獨立遮蔽輸入與「儲存」／「檢查本機」按鈕。兩列不依服務／Live 模型選取而重新命名或共用同一把金鑰；尚未選取音訊來源時也能輸入／儲存。使用的是 API 金鑰，網頁登入本身不適用。

2026-10-25：同一服務頁可選 OpenAI gpt-live-transcribe、Gemini Transcribe Live 或 Gemini 3.5 Live Translate（中文串流），「儲存服務與偏好」只寫模型／供應商、來源語言與品質，不讀取或儲存金鑰欄位。金鑰仍須各列按「儲存」。來源／語系／品質及開始／停止／清除位於主頁，設定原位展開；系統狀態與錯誤只在主頁。Gemini 無音訊診斷使用所選 Gemini 模型，會先回主頁，不擷取音訊。新 Live 模型不改變 Prepared 的既有供應商路徑或 WinCred 名稱。新模式限制與人工步驟見 [ADR 0098](adr/0098-live-model-profiles-native-captions-and-main-source-controls.md) 及 [Phase 11 手動驗收](phase-11-manual.md)。

## 當次使用

模型／語言／品質先在取用金鑰前檢查。Live Translate／GPT 目前需明選五語之一，語言索引零顯示「請手選語言」並停用開始；Gemini Transcribe Live 才提供 Auto。無效選項的直接開始或 Gemini 診斷不消耗／清空尚未儲存的遮蔽輸入，不建立後端；修正選項後才沿用下述有效開始流程。固定儲存及本機檢查不受語言待選影響。此為目前程式整合能力限制，不是金鑰或來源故障，見 [ADR 0100](adr/0100-live-option-capability-preflight.md)。

在所選服務的欄位輸入，選擇來源／服務／語言／品質後按「開始翻譯」。開始只讀所選服務的欄位，取用後立即清空兩列與復原紀錄；不能將另一列的值交給所選服務。未按儲存時不寫入 Windows 認證管理員、一般設定或日誌。留空時由既有啟動流程讀取該服務的安全憑證；欄位不預先讀取或回填已儲存的金鑰。

## 明確儲存

按對應列的「儲存」才寫入或取代此 Windows 使用者在本機認證管理員的該服務金鑰。操作清空該列的輸入／undo，保留另一列以供後續操作；輸入錯誤或儲存失敗也清空已取用的欄位，顯示安全的失敗訊息。空值不寫入、不刪除既有金鑰；沒有自動儲存、顯示／複製舊金鑰或刪除功能。

儲存與開始翻譯是不同動作：儲存不需音訊來源、不擷取、不連線。介面回報已儲存時同時提示「尚未驗證服務端權限」，不能當成有效服務驗收。翻譯執行期間兩組欄位與儲存按鈕均鎖定；停止回收後可再操作。

## Gemini 無音訊診斷

主視窗「Gemini 診斷（連線、不傳音訊）」與「檢查本機」不同：使用者明確按下後才向 Google 查詢固定模型並初始化串流，無需選音訊來源，不擷取或傳音訊／字幕、不自動翻譯。只使用 Gemini 欄位，留空讀取已存 Gemini 憑證；只清空該欄位及 undo，不讀另一服務以補救。採目前來源語言、原固定模型／TLS／WSS，模型資訊與初始化結果分開；不切服務／模型、不重試或跟隨重新導向。單一 worker／結果、三十秒總期限，可按停止取消。結果只在 RAM，查詢或初始化成功不替代真實辨識／翻譯驗收。見 [Phase 11 診斷](phase-11-gemini-diagnostics.md)。

## 資料與驗證

輸入最多 1280 個 ASCII 字元／2560-byte UTF-16LE blob，排除空白、控制字元與非 ASCII；程式設定文字繞過原生輸入上限時也會拒絕，不能接受截斷後的前綴。Rust 的暫存 UTF-16／byte buffer 及 ApiKey 使用 Zeroizing，沒有可序列化金鑰、普通設定寫入或 tracing 內容。原生 EDIT 在取用／關閉時清空並丟棄 undo；不宣稱 Windows 內部或服務端所有副本都能由本程式抹除。

新增六項原生隱藏視窗測試：固定標籤／遮蔽／原生字型寬度與排列；每服務正確取用／清空 undo；非法／程式輸入超限拒絕；兩個 Save 路由與沒有 backend 啟動；空值／非法／儲存錯誤不假成功；執行中鎖定與忽略 Save 通知。所有輸入為合成測試值，Save 使用明確 mock；既有 WinCred round-trip 只操作唯一 SubtitleNow/Test 路徑。原生查詢不等同於完整實機鍵盤／視覺或正式 API 驗收。

首次完整測試中的原生字型寬度檢查發現 OpenAI 標籤區過窄，已加寬至 180 DIP 並保留完整字型量測，沒有放寬測試或 lint。修正後六項 targeted 測試通過；cargo fmt --check、cargo clippy --locked --all-targets --all-features -- -D warnings、cargo test --locked --quiet、cargo build --locked 與 cargo build --locked --release 全數通過。完整一般測試 280 項（254 library、12 設定、4 探索、10 啟動），既有 14 ignored 的組成與另由正常 parent 執行的隔離 GUI 資源 fixture 不變，沒有新增 ignored／相依套件。Phase 5／6 的實機、正式服務及端到端驗收狀態維持待完成。
