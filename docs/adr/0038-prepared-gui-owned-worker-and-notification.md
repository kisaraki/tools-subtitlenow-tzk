# ADR 0038：Prepared GUI 的工作持有與完成通知

日期：2026-10-12

狀態：採用；Phase 08 第三批。本機外掛字幕準備入口，媒體解碼、ASR、播放與音訊定位另列待辦。

前兩批已提供本機文件與全文翻譯，但沒有一般 GUI 操作入口。採用主視窗的「預先準備（本次）」按鈕及獨立的原生準備視窗；使用者明確指定本機媒體、SRT／WebVTT 外掛字幕及字幕語言。輸入只做有界路徑語法驗證，不在 UI 執行緒讀檔或依檔名猜測配對。

準備視窗擁有一個 PreparedBackend，正式實作為 PreparedController。它在 UI 執行緒持有 PreparedSession；每次明確準備只建立一個工作執行緒與 current-thread Tokio runtime，完成以容量一的通道回傳。UI 定時 poll 只在執行緒已退出時 join，然後核對目前 Session 並 apply。Ready 文件只有 owner 的借用，不複製到 widget、通知或第二條時間軸。

取消立即撤回 Session／Ready，讓正在輪詢的 task 收到取消；尚未回收的工作維持 Stopping。新要求必須等待原工作被 poll 回收，不能重疊建立 runtime。關閉先取消，保持訊息迴圈與狀態輪詢直到工作退出；父視窗銷毀或 WM_QUIT 也保留 Rust owner，取消後再回收。controller Drop 的 join 是安全網，不以 detached thread 逃避生命週期。已開始的本機檔案系統呼叫仍要等返回後的取消檢查點，不能宣稱可強制中斷 OS 讀取。

五語原文使用明確選定的 OpenAI／Gemini；固定兩列遮蔽 API 金鑰，只有按「準備字幕」且輸入有效後才移動所選金鑰。留空僅在工作執行緒讀取所選 Windows 憑證，不彈出背景密碼提示。中文只執行本機臺灣本地化，不讀任何金鑰、不建立 client；兩個原生金鑰欄與 undo buffer 都清除。本次輸入不寫入設定或認證管理員；既有主視窗的明確儲存功能保持原意。

服務建立前後都檢查 task 是否取消，停止後不發送新翻譯。傳送用途與實際服務主機顯示在準備視窗，原文字幕與翻譯脈絡只送所選服務；本批不擷取或上傳媒體音訊。工作期間鎖定來源／服務／品質／金鑰；Ready 仍固定本次來源，清除後才能改下一份資料。主視窗在 modal 期間停用，Live 開始與第二個 Prepared 入口也核對 owner enabled，防止訊息繞過互斥。

每次 Ready 只呼叫一次 Windows Shell 完成通知，內容是固定一般文字，不含路徑、片名、字幕、金鑰或服務 payload。通知區圖示由 HWND／uID 識別，重新準備、取消、清除及銷毀撤回；通知不可用時保留 Ready 並明確顯示通知失敗。Windows 自身的通知設定可能抑制顯示，API 成功不等同於使用者確實看到 popup。

所有來源、本文、詞彙與結果仍只有本次 RAM。UI 不提供保存、匯出或播放按鈕，明確標示播放尚未提供；Ready 僅代表字幕文件已準備，不作為媒體解碼、影片配對或音訊定位證據。後續播放仍須交付同一 TranscriptTimeline，依實際音訊核對位置，不能僅依牆鐘推進。
