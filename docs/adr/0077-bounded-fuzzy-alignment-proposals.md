# ADR 0077：有界模糊字幕定位候選

日期：2026-10-22。狀態：Phase 09 第一批採用。

## 決策與原因

現有 `ExactCueVerifier` 的唯一完整 cue、同原文語言、原生時間與精確發布驗證是來源採用的保守邊界。ASR 的小幅字詞差異需要另一種搜尋方法，但模糊文字相似無法證明媒體身分、發行版本或播放位置。因此新增純 CPU `locate_fuzzy_cue` 及獨立 `FuzzyCueProposal`，不降低精確門檻，不轉換成採用證據，也不接入仲裁、擷取時鐘或顯示流程。

## 證據與唯一性

文件及擷取使用明確兩份 Session／generation，epoch 由未來 owner 管理。只接收英／日／法／德／韓原文及相同明確語言的最終 ASR，完整 ASR 時間落於實際擷取視窗；不使用 Ready 時刻或假擷取戳記。中文必須日後有同版本來源參考驗證，不拿已翻譯文本當證據。

以 Unicode scalar 計算帶狀 Levenshtein，僅折疊空白及 ASCII 大小寫，保留標點、詞界、重音。900 的勝出門檻與 50 的次高差距必須同時成立；帶寬涵蓋 850 的競爭者。每個 cue 都參與全文排名，包括未定時與遠處重複，時間不代替文字唯一性。指標是實際編輯一致度，不是內容信心或機率。

## 資源與撤回

沿用原文 8192 cues／四 MiB／每 cue 8192 bytes 契約。每段最多 256 個正規化 scalar，全文 2,097,152 個 recurrence cells，三秒工作期限與原擷取視窗五秒期限取較早者。超量、取消或過期均整次明確失敗，不能以較早找到的好結果掩蓋尚未搜尋的歧義。正規化、逐 cue 與 DP row 均檢查取消。兩列 DP 固定容量，沒有全文複製或索引快取。

這一批沒有正式呼叫者、worker／queue／runtime；未來必須交付有界 CPU lane 並持有取消生命週期。同步核心不能直接跑在擷取、UI 或 async executor。暫不增加另一套全程序 CPU pool，也不宣稱已完成排程／過載測試。

候選不持有本文／文件、沒有 Debug／Clone／Serialize 或採用轉換。交付後 `validate` 仍核對 token、視窗期限、epoch、文件／擷取身分與完整 ASR binding。owner 必須在換文件／發布／來源／seek 時更新 epoch，在同一 binding 本文更改時更新 revision 或撤回 token；未履行這項契約不能靠候選自行偵測。範圍 getter 只返回原始觀測資料，不做媒體 offset 或時間外推。

## 後果與驗證

全文掃描可能因長 cue 或運算預算不足而無候選，優先避免假唯一性。這是明確限制，不偷偷放寬條件或切換服務。尚未完成多觀測錨點、版本驗證、媒體目前位置、seek／pause、offset／drift、中文及 Prepared 辨識 adapter。精確採用、單一時間軸與 capture-only clock 保持原行為。

合成測試核對五語 Unicode、帶寬與不受限演算法比較、勝出／差距邊界、遠處／未定時重複、時間／身分、文字與 DP 上限、取消／期限及候選失效。沒有安裝依賴、unsafe、網路、永久內容、音訊保存、遙測或讀取金鑰。實際驗證見 [Phase 9](../phase-9.md)。
