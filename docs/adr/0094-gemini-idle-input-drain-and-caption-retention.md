# ADR 0094：Gemini 輸入閒置收尾與字幕保留

日期：2026-10-25。狀態：採用；Phase 11 暫停播放的收尾修正。

後續使用者要求由按鈕控制清除，顯示保留／停止清除部分由 [ADR 0095](0095-user-owned-bounded-subtitle-display-history.md) 取代；本 ADR 的輸入閒置收尾、期限及後端取消規則保持。

使用者回報 PID 27032 的快速長句仍換得太快，影片暫停時翻譯停止並消失，要求完成已收到的文字並保留字幕。本批補上程式缺少的音訊中斷收尾，並驗證翻譯與顯示不依賴新音訊；實際消失時的狀態仍待回報，不單憑現象斷言所有錯誤均出於此路徑。

後續使用者貼出 PID 6108／Gemini 仍「正在翻譯」，未有錯誤文字，因此不能把消失直接歸因重連。另查到 renderer 只取最後一列，若新列尚無中文便用空字串覆蓋底部；SideChat 自動跟隨也可能被純原文長尾推走原本可讀的中文。

官方 [Live Transcribe](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe) 支援 `audioStreamEnd`；[Auto VAD 指引](https://ai.google.dev/gemini-api/docs/live-api/capabilities) 說明音訊資料中斷超過一秒時應送此訊號排出緩衝，[WebSocket reference](https://ai.google.dev/api/live) 允許用新的 audio 訊息重開同一串流。查閱日期 2026-10-25。現有設定保持 Auto VAD，不改模型、服務、語言、傳輸或認證。

Gemini 記錄最近一次交付音訊的本機傳送活動時刻。閒置 1100 ms 且真實輸入佇列為空、前處理待回覆數為零、送出佇列排空後才送一次 `realtimeInput.audioStreamEnd=true`；新 PCM 會重新啟用這個閒置偵測。使用原有 100 ms 檢查節拍與有界傳送期限，不新增執行緒、音訊副本、假 PCM 或錄音。待處理計數只計既有有界管線，不新建佇列；OpenAI 不產生此訊號。

一次排出請求從該次訊號起使用原八秒 Final 回覆期限，不反覆重設；真正服務不回覆仍回報錯誤。Final 到達即退休原辨識關聯，後續正常閒置不再被原 Partial 的八秒期限誤判。心跳、整體連線輪替、音訊新鮮度與翻譯期限不變，不以重試掩蓋服務錯誤。

音訊閒置不取消翻譯 Future、不送清空 UI 的 terminal frame；已收到的原文繼續由原 LiveTranslation 完成，側邊與底部共用既有時間軸快照。第一版仍串流，新原文版本保留可讀舊中文直到新版本完整。沒有用暫停保留的文字冒充新 Session、定稿或定位證據；明確停止、換來源、實際錯誤／重連仍沿用取消及清除。這也不推論真正播放器按鈕狀態，閒置時刻不進入擷取或播放時鐘。

顯示層改從當前快照選最近有中文的列，中文＋原文保持同段，尚未有任何中文時仍允許原文預覽。SideChat 只在自動跟隨且無搜尋時暫不投影最新有中文段之後的純原文尾段；原始 rows 不刪除，手動回看／搜尋仍含所有原文。新段中文可用就恢復顯示，沒有另留文字副本、把舊字套至新段或放寬版本／Session 核對。新尾段無譯文沒有 render ticket，不以顯示上一段冒稱新段已呈現。既有來源與定位規則不變。

新增 localhost WebSocket 回歸先在舊程式實際失敗：無新增 PCM 時未送收尾、無法取得模擬 Final，四秒測試期限到達。修正後驗證兩次輸入／暫停／Final 使用同一連線及 Session；純協定測試核對首次、門檻前、有待處理、只送一次、恢復、OpenAI 隔離與真正逾時。共用 LiveTranslation／UI mailbox 測試核對無新音訊仍完成待譯、保留兩種顯示、直到明確停止才清除。具體結果另列診斷紀錄；不以 mock 結果冒稱真實 Gemini 暫停或長句品質通過。

另以有中文前段＋無中文尾段的共享時間軸快照，核對兩種顯示的保留、原文搜尋仍可見、同段原文配對、新中文到達後顯示及明確停止清除。
