# ADR 0092：避免持續暫定辨識取消所有翻譯

日期：2026-10-25。狀態：採用；範圍為 Phase 11 的 Live 排程修正。

## 原因

Gemini 連續轉錄後，使用者回報只有暫停 YouTube 才出現中文。本機以每 40 ms 新增一版相容暫定原文、翻譯端延遲 240 ms 重現：原 Live 流程持續取消已啟動要求，一直沒有中文；1.2 秒回歸期限失敗。原 debounce 已能合併尚未啟動的要求，但無法保護正在進行的翻譯。

## 決定

只在 LiveTranslation 的入口合併正在翻譯的 Partial 後續更新。來源必須同 Session／generation、utterance、sequence、語言及時間 metadata；新 revision 遞增，且原文以正在翻譯的原文為前綴。每段僅保留最新一版，總數不超過既有 MAX_TIMELINE_ITEMS；每筆仍受 MAX_TRANSCRIPT_BYTES 限制，不新增 worker、API permit 或無界佇列。

相容更新暫時不改寫共享時間軸的來源，讓目前已啟動的翻譯串流繼續輸出中文。要求完成並套用後，下一次輪詢再送最新原文。原時間軸本來就保留既有暫定中文，在新修訂待譯時避免閃爍；**不放寬 TranslationUpdate 與來源 revision／job 的精確核對**，不把舊結果強制套到新來源，也不建立第二份時間軸。這會讓正在翻譯期間的可見原文採樣稍慢，受原要求期限約束，換取持續語音仍可先顯示相容的暫定中文。

原文回退或改寫、Final、來源 metadata 改變仍立即走原本的失效／取消流程；Final 不必等 Partial 翻譯完成。合併槽也保留最新 revision 水位，舊修訂不能覆蓋它。退休的時間軸項目與被取代的槽會清除；停止／來源切換／Session 取消不釋放舊槽重新排程。

每筆合併原文在接收當下記錄原本三秒翻譯期限。交給核心時沿用該絕對期限，不能因等待或重新送入而延長；目前要求也保留原期限。Core 的一般 ingest 與 Prepared／既有字幕等直接呼叫路徑維持原策略，只有 Live 採此合併入口。公開 pending_requests 包含等待中的合併槽，API 並行與品質策略保持原限制。

## 驗證與限制

以明確 mock 驗證持續 Partial、沒有 Final 或暫停時就有中文；另驗證每段只留最新、回退／Final 取消舊要求、期限不重設、停止不重送及多批中文串流完整結束後才接續最新原文。結果記錄於 Phase 11 診斷，不以模擬延遲當成真實服務 benchmark。原精確來源採用、媒體定位、擷取時鐘、音訊期限及秘密／內容持久化規則不變；真實 Chrome 中文延遲仍需使用者固定介面驗收。
