# ADR 0103：Auto 待確認語言時限次要求真正定稿

日期：2026-10-26。狀態：採用，Phase 11 人工回報修正。

## 原因與證據

使用者回報新版：音訊收到／送出各 915 包、服務訊息 18、partial 17、final 0、交付 0，最後 LanguageNotReported。確認辨識回應已到達，而當時沒有可供五語核對的語言資訊；不能把這組資料當作服務完全沒回覆，也不能推論尚未收到的 final 一定沒有語言。

ADR 0102 的八秒總等待避免無限續期，但既有音訊閒置排出只在資料中斷時發生。持續播放會一直送音訊，無法在該期限前主動要求定稿；來源語言需等 final 才可核對的合法回應序列因此無法通過。新增本機 WebSocket 以這種序列重現，不收集真實音訊或本文。

官方 [Live Transcribe 收尾指引](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe) 支援 audioStreamEnd 要求服務排出真正定稿，[Live API reference](https://ai.google.dev/api/live) 允許後續音訊重新開啟串流。訊號不代表已取得 final，不是語言回報或定位證據。

## 決定

只有 Gemini Transcribe Live／Auto 已收到待核對的 partial 時，從第一個待確認 partial 起等兩秒，再限次送一個 audioStreamEnd。兩秒為原八秒總期限保留六秒服務回覆空間，不另加或重設期限。等待語言期間若已因真正輸入閒置送出收尾，本段不得重送。尚無轉錄前的一般閒置不能虛構為特定服務段落的完成。訊號不暫停擷取、前處理或後續音訊，也不讓 UI 提早顯示未核對文字。

取得有效 partial 語言即可沿用原 fast path，不必特別收尾。收尾後仍必須等服務實際事件：有五語語言才交付，真正 final 才退休本段。沒有 final／語言仍在原八秒期限失敗，支援外語言拒收；不改成英文、放寬白名單、提高佇列容量、延長音訊期限或猜測本文語言。實際 final 退休後下一段重新核對，不沿用上一段語言；沿用原有界翻譯管線，沒有新增第二條辨識／翻譯管線。

這是已送音訊前綴的處理邊界，不宣稱兩秒就是完整句子或自然語音結尾。真實長句、語言辨識品質及首次字幕延遲仍需人工驗收；不以模擬服務的即時回應宣稱產品達成延遲目標。

既有純數值進度增加一個飽和計數「語言收尾要求」，只在 send 成功後增加。計數代表送出控制訊號，不代表服務已定稿。OpenAI、明選語言及 Native Live Translate 的流程不變，既有一般閒置排出保持。

## 驗證與限制

本機 WebSocket 在持續合成音訊下只於收到收尾訊號回傳有語言的真正 final，連續兩段分別為英、日；檢查 partial 未驗證時不交付、服務完成才退休、音訊不中斷及取消。協定測試涵蓋門檻、每段一次、閒置去重、總期限不續期、已知語言／其他模型隔離及未收到 final 時不製造完成。

不改 TranscriptTimeline、Session 身分、Capture／LivePlaybackClock、ExactCueVerifier、翻譯品質或持久化政策。實際服務是否於收尾後回報 final／語言仍待人工驗收；不宣稱本機合成服務代表真實模型行為。命令結果與部署見 [Phase 11 診斷](../phase-11-gemini-diagnostics.md)。
