# ADR 0027 — 完整來源字幕與最終 ASR 產生保守定位證據

日期：2026-10-10。狀態：Phase 7 第六批採用。

仲裁已有明確證據入口，但查詢成功或翻譯完成並不代表播放位置正確。先提供可實際計算的完整 cue 驗證，作為 Phase 7 採用來源字幕的必要前置；Phase 9 的 fuzzy match、seek、offset／drift 與持續播放校正仍保留。

ExactCueVerifier 接受有效查詢出版物、所屬仲裁版本、實際捕捉視窗與最終 ASR。只接受五種來源語言且語言已知並一致；完整文字僅容許 ASCII 大小寫及空白差異，保留標點與詞界。全文包括其他位置及未定時 cue 都納入重複檢查，避免把副歌或相同對白誤認成唯一位置。至少八個字母／數字是保守工程門檻，不是語言學上的足夠辨識保證。

ASR 起點用來映射唯一 cue 的媒體起點；兩個時間軸的原值保留，不將文件零秒或牆鐘當播放位置。實際 ASR 長度不得超過 cue，長度比值須至少 900／1000，且完整映射 cue 必須位於提供的捕捉視窗。比值是量測時間一致程度，不是命中機率；內容信心仍沿用辨識服務原值與既有 850 門檻。這只驗證一個已觀測片段，不外推後續播放，也不處理字幕延長顯示、重複副歌或缺少可靠時間的資料。

全文掃描使用有界 spawn_blocking；process-wide permit 數依 available_parallelism、上限二個，飽和直接回報而不另建等候佇列。取得 permit 的工作可能等待 Tokio blocking pool，仍維持有界並計入原期限。每個物件只處理一個 mutable future，工作期限取原五秒查詢期限與三秒驗證預算較早者。Drop／取消 abort 尚未執行的工作；已執行的 blocking 工作逐 cue 檢查取消，permit 保留到 closure 釋放，單個有界 cue 的正規化不能強制中斷。這避免非同步工作執行緒、擷取及 UI 承擔全文 CPU 掃描。

封裝 ExactCueMatch 保留原出版物、ASR 綁定與仲裁版本。prepare_matched 在雲端要求前檢查證據並僅準備命中 cue，定位器停止會取消尚在進行的準備。submit_matched 再核對目前 TimelineBinding、原文字／語言／時間、文件索引、查詢時間及仲裁版本；準備結果不得替換證據指向的 cue。仲裁重設後須以新版本建立定位器；定位器 stop／Drop 撤銷尚未提交的證據，已採用候選沿用查詢／準備 parent 與仲裁失效規則，不由定位器反向取消其他候選。

最終採用仍須提供實際 PlaybackObservation，所有視圖沿用單一 TranscriptTimeline。中文候選尚無同語言 ASR 證據，維持原本明確定位入口；本批不將 Live 譯文當成原文命中的證明。正式 GUI 排程、服務配置及實機驗收待接續，未讀正式金鑰、未建立持久內容或新增雲端目的地。

後續擴充：Phase 7 第八批依 [ADR 0029](0029-paired-source-reference-evidence.md) 加入 provider 聲明同版本來源參考軌的中文定位路徑，沿用完整原文命中與時間核對，仍不以 Live 譯文作為證據。沒有參考軌的中文候選保持上述限制。
