# ADR 0087：以獨立觀測驗證 Prepared 與實際 Live 的對齊

日期：2026-10-23。狀態：採用，實作與工程回歸通過。結果見 [Phase 9](../phase-9.md#第十一批驗證)。

## 原因

文字相似度只能提供候選。Prepared 文件的時間也不能直接當作擷取時間；播放器暫停、跳轉、廣告及不同版本會使舊定位失效。需要可撤回的獨立驗證層，並沿用現有擷取、辨識、翻譯、來源仲裁與單一 TranscriptTimeline。

## 決定

原 ExactCueVerifier 與 lookup／候選程式庫契約保持。新的 Prepared Live 路徑至少需要三筆不同且遞增、不重疊的 Final utterance、sequence 及 cue 範圍，各點文字一致度至少 950／1000、次高差距至少 100。這些是工程門檻，不是內容識別的機率或供應商信心。仍搜尋完整文件，重複句或歧義不能靠猜測位置消除。

驗證以 checked 整數有理數模型比較每個已匹配起訖端點，速率相對差異最多 50,000 ppm（±5%），各端點誤差最多 50 ms。偏移使用有符號 i128；顯示位置只取最新已驗證 Final 的原生媒體終點。私有模型投影只判斷新語音是否符合既有速率，不能用來推進畫面位置，靜音及持續擷取不證明媒體前進。

只有此明確 Prepared 路徑保留最多八筆、三十秒的歷史觀測 metadata，讓數秒長句能累積獨立支持；不保存音訊或本文，不放寬原 hint／lookup 發布期限。每次新匹配仍遵守三秒工作及原擷取窗口五秒期限。已發布位置取歷史期限與最新候選原期限的較早者，最長五秒。來源、修訂、epoch、取消與擷取連續性 guard 可隨時撤回。

CaptureCursor 只能由實際 NormalizedAudio metadata 的連續觀測建立，核對整段歷史範圍，最新擷取須在既有 250 ms 新鮮度內，辨識終點落後不得超過兩秒。窗口只描述最多三十秒的實際連續擷取 metadata，不保留該段音訊。沒有適用擷取時間就明確失敗，不從 ASR 反造窗口。

新點符合速率模型時重新驗證並更新偏移。向前／向後跳轉、重啟、章節或不連續會先撤回舊證據、等待舊工作清理，再以新 epoch 蒐集。未匹配的廣告／版本差異退回 Live AI。最新觀測過期時撤回目前位置並等待新輸入；有界歷史不因正常語句間隔而自動證明新位置。明確暫停、重設、停止及來源清除均撤回證據；停止等待真實清理。

中文 Prepared 主軌須由使用者明確提供本機 SRT／WebVTT 五語參考軌及同版本標識。逐 cue 起點與長度須精確且唯一對應，雙段索引須連續；不從檔名猜版本、不把中文譯文當 ASR 原文。兩軌共享既有 8192 cues／四 MiB 上限。來源字幕 Ready 保留實際翻譯品質，低品質結果不得冒充較高策略。

準備視窗新增「保留」操作，移交真正 Ready 擁有者並返回主視窗；一般關閉仍清除。移交的定位來源只持弱本文，不釘住媒體。使用者自行在播放器播放，再明確選來源及啟動；不自動播放或擷取。主視窗的定位暫停／恢復／重設使用單格 watch 與 checked reset 計數，合併命令不遺失重設。清除 Ready 使舊 lease 失效，但不停止 Live AI。

驗證結果以封裝 VerifiedAlignment 進入現有單一來源仲裁器，再由現有時間軸檢查 Final binding 與擷取範圍。不把 raw fuzzy 候選轉 CandidateEvidence，也不新增辨識／翻譯管線。UI tick 與 worker 完成通知共用同一交付路徑，每個 binding 只交付一次。

## 範圍與限制

沿用單段或相鄰雙段、256 scalar／原 DP／CPU／佇列限制，三段以上或超量明確拒收並保留 Live AI。不是通用播放器控制或逐幀時間碼；播放暫停由語音停止／期限及使用者定位操作處理，沒有 invasive hooks。Phase 08 的格式、Auto、媒體相容性限制保持。

測試僅用合成檔案、明確服務 mock 與隱藏的自有 Win32 視窗。真實媒體、供應商品質、Windows 應用程式相容性與效能數字須另行驗收。有效金鑰依既有決定留至結案固定遮蔽介面手動輸入。無產品內容落盤、永久字幕／音訊、遙測、新依賴或跨服務 fallback。
