# ADR 0029 — 中文候選以同版本來源參考軌產生定位證據

日期：2026-10-10。狀態：Phase 7 第八批採用。

最終 ASR 的語言固定為英、日、法、德、韓，無法直接比對中文候選。若拿 Live 的中文譯文與網路中文文字相符作為定位證據，會把翻譯差異及錯誤混入原文核對。相同 content ID 也不足以證明兩份文字使用同一剪輯版本；現有 provider 會回填 query 的 ID。因此只接受明確配置的文字 provider 在同一出版物中提供中文本文與來源語言參考軌。

新增 ExistingTextBundle／SourceTextReference。兩軌必須具有相同 Session、來源與內容 ID；provider 必須分別聲明本文與參考軌的 edition ID，且兩者相同、非空、無控制字元、各不超過既有 1024-byte metadata 上限。這是 provider 聲明的版本來源資訊，不是密碼學驗證，也不代替內容確認與 ASR 核對；正式 adapter 必須使用服務實際提供的版本及時間資料，不能猜測或只複製歌曲 ID。

兩軌原子驗證及發布，共用一份 query、出版物取消訊號、內容信心與原始期限；不存在獨立刷新或撤銷的參考軌。合計最多 1024 cues／128 KiB 原文，沿用每 cue 8192-byte 上限。更新確認不延長已交付候選的期限，LiveLyrics 撤銷共同出版物時兩軌同時失效。本文與參考軌只在 Session RAM，不增加 Debug／Serialize、內容匯出、檔案或持久快取。

ExactCueVerifier 在完整參考軌找唯一的 Final ASR 完整命中，仍只放寬 ASCII 大小寫與空白，保留原有最短文字、語言、內容信心、時間長度及捕捉視窗門檻。再尋找中文本文中唯一具有完全相同媒體起點與長度的 cue；不假設兩軌索引相同，不用跨語言文字相似度。重複參考文字、重複中文時間範圍、缺少參考軌、不同版本、未知時間或一微秒的時間差均不能產生可採用證據。保守拒收後維持 Live AI。

封裝證據保留參考索引與中文文件索引。中文準備沿用有界 CPU 本地化，不發送 Translator 要求；交付、提交及採用保持原有 Session、ASR 修訂、仲裁 epoch、期限與實際捕捉游標檢查。提交還須以 same_scope 核對準備結果與證據的出版物取消訊號，防止將另一份相同文字及時間的結果套用到舊證據。每候選仍使用原有固定三層取消模型。

排程去重的一筆有界 metadata watermark 納入可選配對身分：兩個 edition ID 與參考語言。相同版本確認仍去重；新版本、參考語言更換或有／無參考軌切換須替換舊工作並清除前文脈絡。相同仲裁版本先檢查 query sequence／時間及 ASR sequence／revision，不讓舊資料藉版本更換取消較新工作。正式排程的拒收路徑忽略此 Lookup(Stale)，保留目前工作與進度；其他錯誤仍清除並提示失敗。此比較不保留另一份原文或譯文。UI 顯示本機臺灣用語處理狀態，來源語言翻譯狀態則繼續提示所選 Translator。

既有 provider 的 lookup_bundle 預設只呼叫原 lookup 一次，回傳未配對本文，沒有新增查詢、服務或自動備援。LRCLIB 仍提供既有單軌資料；一般 GUI 的內容配置仍為 None。正式配對服務、內容／字幕服務配置及真實媒體驗收尚待完成。本批合成測試不代表服務聲明已獲獨立驗證、播放器已同步或延遲已達目標。進階 fuzzy／seek／drift 留於 Phase 9，金鑰與真實雲端測試保持結案時固定遮蔽介面手動輸入。
