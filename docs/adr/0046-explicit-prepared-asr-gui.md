# ADR 0046 — 明確選擇服務的 Prepared GUI 語音辨識

日期：2026-10-13  
狀態：採用於 Phase 08 第十一批；真實服務與播放定位尚待驗收。

## 問題

PreparedSession 已能以同一媒體 pin 建立辨識來源的 Ready，正式 HTTP adapters 也已提供，但一般準備視窗仍要求外掛字幕。直接重用字幕語言或舊的「不傳送媒體音訊」提示會讓實際處理與使用者選擇不一致。金鑰仍須由使用者在結案時從固定遮蔽介面手動輸入，不能在開發或開啟視窗時啟動服務。

## 決策

外掛字幕欄位只有完全空字串才代表本次沒有字幕。非空路徑仍走原有驗證、明確格式／語言及優先規則；不 trim 成空、不用損壞字幕自動轉成音訊上傳。中文仍只本機本地化，來源字幕只建立翻譯服務，不建立 recognizer。

音訊來源語言使用獨立的 Auto／英／日／法／德／韓選擇，不由外掛字幕語言推論。現有正式 adapters 尚未建立可靠的限五語 Auto 契約，原生視窗在取用金鑰前拒收 Auto，controller 也在建立 worker／讀憑證／媒體 I/O 前防禦性拒收。外掛字幕路徑忽略音訊語言，不因 Auto 阻止原有字幕準備。

無字幕時必須明確選擇 OpenAI 或 Gemini。固定目的地列在按準備前說明：短片段媒體音訊送到所選服務辨識，辨識原文與翻譯脈絡送到同一服務翻譯；所有內容只在本次記憶體，不加入來源路徑或切換供應商。輸入欄變更立即刷新用途，目的地與按鈕留在捲動內容之外。底帶高度依同一原生 EDIT 的實際字型與折行調整，借用 DC／字型由 RAII 還原及釋放，避免窄視窗只顯示部分用途；內容捲動與焦點可見性沿用實際 viewport。

PreparedController 的私有 factory 以明確的 Translation／Recognition kind 建立服務。每次只解析一次所選的 ApiKey：有本次輸入就使用該值，否則在背景 worker 讀取該服務的 Windows 安全憑證。Recognition 以同一服務與 key 建立 HttpPreparedRecognizer 及 HttpTranslator；不複製 ApiKey、不查另一服務、不寫憑證、未建立完成前不送出媒體要求。原生欄位取用後清除雙列與 undo，錯誤／取消／清除／關閉同樣清理。

GUI 使用固定的 16 kHz 單聲道 Prepared 前處理，不增加取樣率設定。既有 owned worker 呼叫 run_with_recognizer，保留一個 Session、一個可回收工作執行緒及容量一的結果通道；不建立第二條字幕時間軸。CPU／native-owner／HTTP 資源限制仍由原有 pipeline 控制。UI 不讀媒體或等待網路，停止後保持 Stopping，直到工作與 runtime 內已開始的 blocking worker 真正退出才接受下一份。

Ready 仍只代表完整的本次文件，沒有自動播放、字幕匯出或持久快取；原媒體 pin 持續到文件清除。原生完成通知維持固定一般文字，不含路徑、辨識本文或金鑰。播放與音訊重新對齊、seek、其他容器、內嵌字幕、URL、全文專名／詞彙分析及 Auto 仍待接續。

## 驗證與限制

原生隱藏視窗與明確 mock／合成 WAVE 用於驗證操作路由、用途揭露、金鑰隔離、原生時間、取消及 pin 回收。Auto 專用提示限於本次無字幕且音訊語言仍為 Auto 的本機拒收；明確語言或服務回應的 UnsupportedLanguage 保留通用 typed 原因。正式 factory 的建構可用合成 key 驗證，但不送網路要求，也不讀取正式憑證。這些證據不代表實機鍵盤／視覺驗收或真正五語雲端辨識品質。

實際指令與測試數見 [Phase 8 第十一批驗證](../phase-8.md#第十一批驗證)。Phase 08 尚未完成，Phase 09 尚未具備啟動條件；有效金鑰維持結案固定介面手動輸入。
